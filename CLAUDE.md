# CLAUDE.md, boilerplate-symfony

Boilerplate personnel. Les conventions générales sont dans `~/.claude/CLAUDE.md` : ce fichier ne note que les choix propres au projet.

## Choix du projet

- **Type** : application Symfony rendue côté serveur. Twig produit tout le HTML, Stimulus et Turbo ne font qu'enrichir. Chaque page fonctionne sans JavaScript : le carrousel défile nativement et ses boutons sont masqués, les filtres du catalogue et le contact sont des formulaires classiques, la page Tâches remplace son squelette par un lien vers `/taches/liste`, qui rend alors la page complète (noindex, canonique vers `/taches`) au lieu du seul contenu du frame.
- **Architecture** : découpage par module puis par couche (`src/<Module>/<Couche>/`), selon l'architecture DDD commune aux boilerplates (D1 à D12). Modules métier : `Catalog` (forme complète : `Application/ShowCatalogPage` porte les décisions, catégorie inconnue ou page hors bornes renvoyées comme `null` que le contrôleur traduit en 404, échec du dépôt renvoyé comme page en erreur), `Blog`, `Contact`, `Task` (forme réduite, sans couche Application : l'UI appelle directement le port du domaine, conformément à la règle « Application apparaît au premier cas d'utilisation qui décide »). Le contrôleur du catalogue ne garde que la normalisation de l'URL (redirection 301 vers la query string canonique), avant d'appeler le cas d'utilisation. `Site` porte les pages sans métier (accueil, légal, SEO, charte) et compose les modules. `Shared` est le socle sans métier (SEO, fil d'Ariane). Les couches portent leur nom DDD : `Domain` (sans framework), `Application`, `Infrastructure`, `UI` (contrôleurs minces, la couche de routage, et leurs formulaires et extensions Twig). Côté templates, `templates/shared/` remplace `core/` et `features/`.
- **Suivi des erreurs** : GlitchTip, par les SDK Sentry, activé seulement si `GLITCHTIP_DSN` est renseigné (`.env.local`, jamais versionné). Vide par défaut : aucun script, aucune requête. Côté PHP, `config/packages/sentry.yaml` : pas de donnée personnelle, pas de corps de requête, pas de traces, et les erreurs attendues (404, 405, 422, 503) ignorées. Le catalogue et le contact rendent leurs 503 et 422 sans lever d'exception, ils ne sont donc jamais remontés. Côté navigateur, `App\Shared\UI\Twig\ObservabilityExtension` n'expose la configuration aux templates que si elle existe. Le contrôleur Stimulus `glitchtip`, chargé à la demande, injecte le SDK après l'événement `load`, une seule fois par visite.
- **Mesure d'audience** : Matomo sans cookie, donc sans bandeau, activé seulement si `MATOMO_URL` et `MATOMO_SITE_ID` sont renseignés. Le contrôleur Stimulus `matomo`, chargé à la demande, pose `disableCookies` avant toute autre commande et charge `matomo.js` en asynchrone. Turbo remplace `<body>` à chaque navigation : chaque connexion du contrôleur compte une page vue, et `turbo:frame-load` compte aussi les navigations de frame qui changent l'URL (filtres du catalogue). La page « Données personnelles » ajoute un paragraphe « Mesure d'audience » seulement quand Matomo est activé. Le visiteur peut s'y opposer depuis la page Données personnelles (contrôleur `opposition-mesure`, fiche CNIL n° 17, section 16 de la spec commune) : le refus est gardé dans le stockage local (`assets/opposition_mesure.js`), lu par le contrôleur `matomo` avant toute commande et avant chaque page vue ; posé, aucune commande ni requête. La page n'affirme pas l'anonymisation de l'IP : réglage de l'instance, à activer avant la mise en ligne.
- **CSP** : `Content-Security-Policy-Report-Only` sur chaque réponse principale, par le paquet `kewinmarchand/csp` (dépôt GitHub déclaré en `repositories` de `composer.json`), utilisé seulement dans `src/Shared/Infrastructure/Security/` (`make arch-wrappers`). `SiteCsp::subscriber()` fabrique l'abonné du paquet (`config/services.yaml`) : directives par défaut, plus l'origine de `API_URL`, et celles de Matomo (script, appels, pixel) et de GlitchTip (envoi) quand leurs variables sont renseignées, lues à l'exécution (`%env()%`). Route `POST /api/csp-report` (`config/routes.yaml`, contrôleur du paquet) : une ligne par rapport sur la sortie standard du conteneur, 413 au-delà de 10 000 caractères, 400 sur un JSON invalide. Le `CMD` du `Dockerfile` écrit d'abord `[boilerplate-symfony] serveur démarré (<APP_ENV>)` (`docker/startup.php`) : PHP n'a pas de démarrage d'application propre. Couvert par `SiteCspTest`, `CspTest` et `tests/e2e/csp.e2e.ts`.
- **Tests d'observabilité** : `make test-e2e` relance l'image de production avec des valeurs factices (`OBSERVABILITY_ENV` dans `Makefile.qa.mk`) pour les tests marqués `@observabilite` : un faux GlitchTip local sur le port 3231, et un traceur Matomo factice intercepté sur `http://matomo.test/`. Aucune instance réelle n'est contactée. La CSP autorise les origines de Matomo et de GlitchTip quand leurs variables sont renseignées.
- **API commune** (spec commune, section 6) : `API_URL` choisit l'API, 8090 pour API Platform par défaut et 8091 pour Hono, sans autre changement de code. Un seul client, `api.client` (`config/packages/http_client.yaml`, `base_uri` et `Accept: application/json`), injecté par son nom `$apiClient`. `App\Shared\Infrastructure\Http\ScenarioRelayHttpClient` le décore pour relayer `X-Scenario` depuis la requête en cours. deptrac interdit le client HTTP hors des couches Infrastructure. Les API publient leur port sur `127.0.0.1` seulement : le service `php` est donc, comme `node`, sur le réseau de l'hôte (`network_mode: host`), et Caddy écoute sur `SERVER_ADDRESS` (`127.0.0.1:${HTTP_PORT}` en Compose, `:8080` par défaut dans l'image). Réseau de l'hôte réservé à Linux : sous Docker Desktop, il faut une API publiée sur toutes les interfaces et `API_URL=http://host.docker.internal:8090`.
- **Chemin de catégorie** : `App\Catalog\Domain\CategoryPath` est le seul point qui transforme le paramètre d'URL `plantes-interieur/feuillages` en catégorie (`resolve()`, `null` si un slug est inconnu ou si la profondeur dépasse 3). Le contrôleur en fait un 404, les templates en tirent le fil d'Ariane (`steps`), les liens enfants (`child`), le menu mobile et le sitemap (`catalog_paths()`).
- **Données** : aucune base, tout vient de l'API commune (`API_URL`). Chaque module traduit l'API dans `src/<Module>/Infrastructure/Http/` (traduction et dépôt HTTP), à l'aide de `App\Shared\Infrastructure\Http\ApiPayload`, qui vérifie la forme de chaque champ. Pas de génération de types en PHP : la traduction est le contrat. Erreurs réseau, 4xx et 5xx deviennent l'exception de chargement du module (états d'erreur avec relance). Le 422 du contact devient `ContactMessageRejectedException`, dont les violations s'affichent sous les champs du formulaire. Les dépôts en mémoire et `CatalogSearch` sont supprimés. En test, `MockHttpClient` sert des réponses réelles capturées sur l'API (`tests/Fixtures/api/`, `tests/Support/ApiMockResponseFactory.php`, `X-Scenario` compris) : `make qa` ne demande aucune API démarrée. Les diapositives de l'accueil restent un contenu du site (`Site/Home`), sans ressource dans l'API.
- **Prix** : `App\Catalog\Domain\Price` en centimes, comme l'API. Les euros n'existent que dans l'URL (`prix_min`, `prix_max`, convertis par `CatalogUrlState`) et à l'affichage (`Price::format()`, filtre Twig `price`), plus de `* 100` caché dans le filtre.
- **Config du site** : un seul fichier, `config/packages/site.yaml` (nom, URL, éditeur, hébergeur, audit d'accessibilité, navigation). La navigation alimente le menu, le sitemap, le plan du site et le fil d'Ariane.
- **SEO** : `App\Shared\UI\Seo\SeoPageFactory` est le seul point de construction des métadonnées. Chaque vue commence par `{% set seo = seo_page({...}) %}`, le layout ne fait qu'afficher.
- **Erreurs** : classes `XxxException` du domaine avec un message métier en français. PHP réserve le suffixe `Error` aux erreurs du moteur, d'où l'écart de nommage avec le front.
- **Icônes** : sprite SVG tiré de Lucide (spec commune, section 17). `icons.json` liste les noms utilisés. `make icons` génère `public/icons.svg` (un `<symbol>` par ligne, ordre alphabétique) et `src/Shared/UI/IconNames.php`, la liste des noms lue par la charte graphique. `make icons-check`, lancé par `make qa`, échoue si l'un des deux ne correspond plus à `icons.json`. Le générateur (`tools/icons.js`) tourne dans le service `node` (variable `NODE` du Makefile). Un seul partial affiche une icône : `templates/shared/ui/_icon.html.twig`, `<svg><use href="/icons.svg#nom">`, décorative par défaut, porteuse de sens avec `icon_label`. Le logo reste un SVG propre au projet, hors sprite.
- **CSS** : maison, dans `assets/styles/app.css`, sur les tokens de `@kewinmarchand/boilerplates-ui` (section 19 de la spec commune) : les variables du site (`--color-*`, `--font-size-*`, `--space-*`, rayons, conteneur, focus) sont des alias des variables `--bui-*`, qui portent aussi les valeurs du mode renforcé (tailles, couleurs, épaisseur du focus). Seules les valeurs propres au site restent écrites (`--color-surface-dark`, gouttières, voile du hero, surcharges du mode renforcé : texte secondaire et focus en noir). La bibliothèque est copiée dans `assets/boilerplates-ui/` (versionné) par `make ui` (`tools/ui.js`) depuis la dépendance de dev : la production n'a pas Node, et AssetMapper sert les fichiers tels quels. `boilerplates-ui.css` réunit tokens et composants en une seule feuille (chaque `@import` serait une requête bloquante de plus), chargée par `assets/app.js` avant `app.css` ; ses composants sont dans `@layer components`, la feuille du site, hors couche, garde la priorité. `make ui-check` (dans `make qa`) échoue si la copie ne correspond plus à la version installée. La charte lit les tokens dans `app.css` et résout les alias dans `boilerplates-ui.css` (`DesignTokens`). Composants : les templates écrivent le balisage de référence de la bibliothèque (`packages/css/reference/markup.ts`, classes `bui-*`) : bouton, icône (`_icon.html.twig` pose `bui-icon`), alerte (`shared/ui/_alert.html.twig`, action par `embed` dans le bloc `action`), champs Symfony par le thème `form/bui_layout.html.twig` (enregistré dans `twig.yaml` : libellé, aide, champ, erreur, et « (obligatoire) » écrit dans le libellé, RGAA 11.10, sans astérisque ni phrase générale), cases, boutons radio, interrupteur, fil d'Ariane, pagination (sans flèche inutile, page courante en lien `aria-current`), carte, badge, squelette, puces (`bui-chip` dans une `ul.bui-chip-list` : sous-catégories et filtres actifs retirables, la classe `chips` du site ne porte que la marge). Couches CSS : `assets/styles/layers.css`, importée en premier, pose `@layer base, components;` ; les styles d'éléments du site (`a`, `p`, titres, `img`, focus) sont dans `@layer base`, sous les composants, et les règles de classes du site, hors couche, gardent la priorité. Sans cette couche, `a { color }` écraserait la couleur d'un `bui-button` posé sur un lien. Le mode renforcé ne fait que surcharger des tokens sous `:root[data-a11y-mode='enhanced']`. Les espacements WCAG 1.4.12 ne s'appliquent qu'au texte de contenu de `<main>`.
- **Unité de police** : `px`. Police Inter variable (fontsource 5.3.0) servie localement depuis `assets/fonts/`, licence OFL jointe.
- **Cibles tactiles** : 44 px minimum (`--touch-target`).
- **Langue** : français uniquement, URL en français.
- **Développement en conteneur** (spec commune, section 18) : seuls prérequis, Docker, `make` et git. PHP passe par le service `php`, Node par le service `node` (`docker/node/Dockerfile`, image officielle Playwright à la version exacte de `@playwright/test`, épinglée dans `package.json`), sous le profil Compose `dev`. Le service `node` est en `network_mode: host` : Playwright et Lighthouse y joignent l'image de production et le serveur de dev sur 8095, Lighthouse sur 3230 (un autre projet Compose) et le faux GlitchTip du test sur 3231, sans configuration réseau. La CI n'appelle que des cibles `make`.
- **Hook git** : aucun, et donc pas de lint-staged. Toutes les commandes passent par Docker, un hook de pré-commit imposerait la stack démarrée à chaque commit ou serait contourné. La CI fait foi.

## Ports et projet Docker

- Nom de projet Compose explicite (`name:` dans `compose.yaml`) pour ne jamais toucher aux autres stacks de la machine.
- Port 8095 pour le dev et Playwright (`HTTP_PORT`), lié à `127.0.0.1`. Lighthouse lance un second projet Compose sur le port 3230.
- Aucune base, donc aucun port PostgreSQL.

## Règles d'architecture et de lint propres au projet

Vérifiées par `make arch`, lancé par `make qa` et donc en CI :

- **deptrac** (`deptrac.yaml`, règle R12) : `Domain` ne dépend que de lui-même (ni framework, ni autre couche, ni autre module), y compris par un nom pleinement qualifié. `Application` dépend du `Domain` de son module. `Infrastructure` du `Domain` et de l'`Application` de son module et des frameworks. `UI` du `Domain` et de l'`Application` de son module, de `Shared` et des frameworks, et de l'`Infrastructure` seulement pour `Contact` et `Task`, qui n'ont pas de couche Application. `Site` peut dépendre du `Domain` et de l'`Application` des modules. `Shared` ne dépend que des frameworks. Les classes natives de PHP (`\DateTimeImmutable`, `\NumberFormatter`, exceptions) ne sont dans aucune couche et restent permises partout : elles ne sont pas un framework.
- **Wrappers** (règle R10, `grep`) : le sprite `icons.svg` n'est utilisé que dans `templates/shared/ui/_icon.html.twig` (hors `assets/vendor/` et de la copie `assets/boilerplates-ui/`, dont le toast et le tableau citent le sprite), Embla n'est importé que dans `assets/controllers/carousel_controller.js`, le paquet `kewinmarchand/csp` n'est utilisé que dans `src/Shared/Infrastructure/Security/` (le reste du projet passe par `SiteCsp`).
- **Auto-test** : `make arch-selftest` (`tools/arch-selftest.sh`) écrit 9 violations volontaires à leur emplacement réel (Domain vers Infrastructure, Domain vers Symfony par nom qualifié, module vers module, Shared vers module, UI du catalogue vers son Infrastructure, UI vers le client HTTP, le sprite utilisé hors du partial, Embla hors de son contrôleur, le paquet CSP hors de `Shared/Infrastructure/Security/`), exige que chacune soit citée, puis retire les fichiers. Une règle qu'aucun test ne viole peut être débranchée sans bruit.

Écarts assumés par rapport à l'arbre cible de l'architecture commune :

- `AccessibilityExtension` (fonction Twig `accessibility_compliance()`) vit dans `Site/Legal/`, pas dans `Shared/UI/Twig/` : elle lit la règle de conformité de `Site/Legal`, et `Shared` ne dépend ni des modules ni de `Site`.
- Les templates ne sont pas couverts par deptrac : les fonctions Twig sont globales, et l'en-tête partagé (`templates/shared/layout/_header.html.twig`) appelle `catalog_tree()` du module catalogue. C'est la composition faite par le layout du site, l'équivalent du menu passé en propriétés par la couche de routage des fronts JavaScript.
- Pas de règle de couches pour les contrôleurs Stimulus : l'architecture ne découpe pas `assets/controllers/` en modules, seule R10 (une bibliothèque tierce dans son seul wrapper) s'y applique.

ESLint (`eslint.config.js`) : seules `simple-import-sort/imports` et `simple-import-sort/exports`, en erreur, sur les fichiers `.js` (`assets/` hors copies tierces, `tools/`), corrigées par `make lint-js-fix`. Groupes : tiers (`node:`, paquets et noms de l'importmap), relatifs, puis effets de bord, que le plugin ne réordonne pas entre eux (les feuilles de style d'`app.js` gardent l'ordre de la cascade, vérifié). Pas de bibliothèque commune, de socle, de modules ni de vues à ranger côté JavaScript. Les tests Playwright en TypeScript n'y sont pas : il faudrait le parseur typescript-eslint.

PHP-CS-Fixer : `@Symfony` plus `declare_strict_types` (règle risquée, activée pour garantir `declare(strict_types=1)` partout).

## Pièges connus, réellement rencontrés

- **Image de dev** : `make up` reconstruit l'image de dev (`--build`, rapide grâce au cache). Le Caddyfile est copié dans l'image : une image non reconstruite sert une configuration périmée, par exemple une écoute sur `:8080` au lieu de `SERVER_ADDRESS`, et la passe e2e en dev échoue dès qu'un autre service occupe ce port sur la machine.

- **Port 8080 occupé** sur la machine de l'auteur (un serveur uvicorn), d'où 8095. Depuis, 8095 peut lui aussi être pris par un autre service de la machine : `make up HTTP_PORT=18095` (ou `make test-e2e HTTP_PORT=…`) déplace le site, Playwright suit la variable.
- **Clés répétées dans l'URL** : PHP écrase `?taille=S&taille=M` en ne gardant que la dernière valeur. `CatalogUrlState` lit la query string brute avec `HeaderUtils::parseQuery($query, true)`. Toute URL non canonique (ordre, valeurs vides ou invalides, défauts) est redirigée vers sa forme canonique.
- **Variable d'environnement réelle contre `.env.test`** : Compose injecte `SITE_URL`, qui gagne sur `.env.test`. `phpunit.dist.xml` la force avec `force="true"`.
- **WebTestCase redémarre le noyau entre deux requêtes** : un service remplacé par `getContainer()->set()` disparaît au second appel. `$client->disableReboot()` quand un test enchaîne GET puis POST.
- **Page 404 personnalisée invisible en test** : l'environnement `test` est en debug et affiche la page d'exception. Créer le client avec `['debug' => false]`.
- **`include` Twig transmet le contexte** : une variable `label` du template appelant ressortirait comme `aria-label` de l'icône. Le paramètre s'appelle `icon_label`.
- **Composants de la bibliothèque et règles du site** : les composants `bui-*` sont dans `@layer components`. Une règle de classe du site, hors couche, l'emporte quelle que soit sa spécificité : c'est voulu pour les surcharges (`.bui-button--outline[aria-current='page']`), mais une règle de mise en page qui vise un élément `bui-*` doit le faire exprès. Les bascules d'affichage préfixent toujours par `.header` ou `.js`.
- **Glisser au carrousel en e2e** : la souris de Playwright n'agit que dans le viewport, faire `scrollIntoViewIfNeeded()` avant de mesurer la piste. Les images portent `-webkit-user-drag: none` pour ne pas déclencher le glisser natif.
- **Pages qui n'existent qu'en dev** : `/_error/500` et `/charte-graphique` sont déclarées sous `when@dev` et `when@test`. Les e2e tournent sur l'image de production, puis `make test-e2e` relance le serveur de dev pour les tests marqués `@dev`. En fin de commande, c'est donc le serveur de dev qui tourne. Chaque cible démarre elle-même l'environnement qu'elle attend, dans sa recette et non en prérequis : dans une seule invocation (`make test-e2e test-a11y`), make ne rejoue pas un prérequis déjà satisfait, et `test-a11y` tomberait sur le serveur de dev, où la 404 est la page d'exception de debug.
- **Cache de test sans debug** : le test de la 404 crée un noyau `['debug' => false]`, dont le conteneur compilé n'est jamais revalidé. Après un renommage de classes, il référence des noms de classes périmés. `make test-unit` vide `var/cache/test` avant PHPUnit.
- **PHPStan et Symfony** : `typecheck` réchauffe le cache dev avant l'analyse, sinon `containerXmlPath` n'existe pas.
- **`localhost` contre `127.0.0.1`** : Chromium essaie `::1` d'abord, et un autre service de la machine peut répondre 200 avec un corps vide sur `[::1]:8095`. Caddy n'écoute que sur `127.0.0.1` : Playwright vise donc `http://127.0.0.1:…`. Lighthouse vise aussi `127.0.0.1:3230`, et `make metrics` lance son site avec `SITE_HOST=127.0.0.1` : l'URL canonique reste sur le même hôte que la page mesurée. Écouter aussi sur `::1` ne marcherait pas sur un poste où un autre service occupe déjà `[::1]` sur le même port.
- **Données de l'API dans les tests** : les textes attendus suivent l'API, avec l'apostrophe typographique (« Plantes d’intérieur »), 7 produits en mi-ombre, 9 en taille L, 1290 et 1590 centimes en tête du tri croissant de `plantes-interieur`. Les états d'erreur et de liste vide passent par `X-Scenario` (`page.setExtraHTTPHeaders`), relayé par le site vers l'API.
- **Charge machine** : avec plusieurs suites en parallèle sur le poste, Playwright dépasse ses délais. Il tourne sur 4 workers en local, 2 en CI.
- **Performance Lighthouse** : l'accueil et le catalogue tournent autour de 0,90 à 0,93. Lighthouse simule un réseau lent où tous les téléchargements simultanés se partagent la bande passante, et le serveur local est en HTTP/1.1 (6 connexions). Causes mesurées : les diapositives du carrousel hors écran se chargent malgré `loading="lazy"` (seuil de Chrome), d'où `content-visibility: auto` sur les diapositives (deux images de moins sur mobile). La première image produit de `feuillages` est l'illustration monstera, qui pèse 159 Ko en 800w, c'est le plancher actuel de cette page. Les mesures en place : préchargement de l'image LCP en tête du `<head>`, `fetchpriority="high"` sur la première image produit, pas de lazy sur les quatre premières, `sizes` alignés sur la mise en page réelle, contrôleurs du carrousel et du catalogue chargés à la demande. Lighthouse fait 3 runs et l'assertion porte sur la médiane, avec un seuil de 0,90 bloquant. La latence simulée des dépôts n'y est pour rien : mesurée à 0 ms, le score de l'accueil ne bouge pas.
- **`catalog_tree()` dans l'en-tête** : il est appelé sur chaque page rendue, pages d'erreur 404 et 500 comprises. Le dépôt HTTP ne fait qu'un appel par requête (arbre gardé en mémoire le temps de la requête), et `catalog_tree()` se replie sur la seule entrée « Catalogue » si l'API est indisponible, pour ne pas casser les pages d'erreur. Un cache entre les requêtes (cache pool Symfony, durée courte) reste à ajouter quand le trafic le justifiera.
- **`APP_SECRET` obligatoire** : `compose.yaml` l'exige (`${APP_SECRET:?}`), sans défaut connu. Compose interpole `compose.yaml` avant de fusionner l'override, donc un défaut dans `compose.override.yaml` ne suffit pas. Le Makefile génère un secret aléatoire à chaque invocation quand la variable n'est pas fournie. Sans `make`, exporter `APP_SECRET` avant `docker compose`.
- **Composer dans le conteneur** : `composer require --dev` a écrit des contraintes `*`, corrigées à la main en `^x.y`.
- **Lighthouse** : Chrome est lancé avec `--no-sandbox` (Ubuntu restreint les user namespaces). Les rapports restent en local dans `.lighthouseci/`.
